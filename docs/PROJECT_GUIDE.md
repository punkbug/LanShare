# LanShare 제품 및 개발 가이드

## 제품 개요

LanShare는 같은 공유기 또는 로컬 네트워크에 연결된 기기 사이에서 파일을 주고받는 앱입니다. 인터넷 기반 파일 보관 서비스가 아니라, 네트워크가 허용하는 전송 성능을 활용해 기기끼리 직접 데이터를 전달하는 것이 기본입니다. 네트워크 장비, Wi-Fi 간섭, 저장장치 성능, 운영체제 정책이 실제 속도에 영향을 주므로 전송 속도를 보장한다고 표현하지 않습니다.

LocalSend에서 참고할 점은 계정과 외부 서버 없이 로컬 네트워크에서 보내는 단순한 경험입니다. Send Anywhere에서 참고할 점은 받는 쪽이 쉽게 연결하고 승인할 수 있는 흐름입니다. 두 제품의 이름, 디자인, 구현 코드, 프로토콜을 복제하지 말고 LanShare만의 구현과 인터페이스를 만듭니다.

## 첫 번째 릴리스: macOS MVP

필수 흐름:

1. 앱을 열면 4자리 LAN 연결 코드를 표시하고 같은 네트워크의 LanShare 기기를 검색합니다. 상대방이 표시한 코드를 입력해 연결합니다.
2. Finder에서 파일 또는 폴더를 선택하거나 앱으로 끌어다 놓습니다.
3. 대상 기기를 선택하고 전송 요청을 보냅니다.
4. 받는 기기에서 보낸 기기, 파일명, 전체 용량을 확인하고 수락 또는 거절합니다.
5. 양쪽 화면에서 전송 진행률, 전송 속도, 예상 남은 시간을 확인합니다. 취소와 실패 이유를 명확히 표시합니다.
6. 수신자는 저장 위치를 선택할 수 있고, 파일이 완전히 저장된 뒤에만 완료로 표시합니다.

초기 버전은 macOS 앱끼리의 파일 전송을 우선합니다. 다만 다음 플랫폼 구현을 막지 않도록 네트워크 프로토콜을 UI와 분리하고, 공개 규약을 별도 문서로 관리합니다. 폴더 전송은 상대 경로와 디렉터리 생성을 안전하게 처리합니다. MVP에서 구현하기 어렵다면 첫 출시 범위에서 제외하고 단일 파일 전송을 먼저 완성합니다.

## 후속 플랫폼

macOS와 Android 간 단일 파일 전송이 동작하며, iOS/iPadOS와 Windows 클라이언트는 같은 개발용 v1 발견·승인·전송 규약을 구현합니다. 공통 wire format은 플랫폼별 네트워크·파일 API와 분리해 `docs/PROTOCOL.md`에 정의합니다. iOS는 전송 중 앱을 foreground에 두어야 하고, Windows는 mDNS 및 TCP 통신을 위해 개인 네트워크 방화벽 허용이 필요할 수 있습니다. 현재 규약에는 전송 암호화와 기기 인증이 없으므로 공개 배포용으로 취급하지 않습니다.

## 기술 방향

- 첫 macOS 앱은 Swift와 SwiftUI 등 Apple 플랫폼 기본 도구를 우선 검토합니다. 실제 구현 전에 저장소 상태와 설치된 개발 도구를 확인하고 선택 이유를 기록합니다.
- 전송 서비스, 기기 검색, 파일 입출력, 화면 상태를 분리합니다. UI 코드에 네트워크 프로토콜이나 파일 쓰기 로직을 직접 섞지 않습니다.
- 프로토콜은 버전 필드를 포함하고, 기능 협상과 오류 응답을 정의합니다. 큰 파일은 메모리 전체에 올리지 말고 스트리밍으로 처리합니다.
- 코드 검색은 같은 네트워크의 mDNS/Bonjour에서 동작하며, 일치한 기기에 TCP로 직접 연결합니다. 앱 간 파일 데이터는 웹페이지, 외부 서버 또는 클라우드를 통과하지 않습니다. mDNS/Bonjour 사용 시 macOS 로컬 네트워크 권한과 배포용 네트워크 설명을 준비합니다.
- 앱이 지원하지 않는 네트워크 환경에서도 원인을 진단할 수 있도록 검색 실패와 연결 실패를 구분합니다.

## 보안 및 개인정보

- 기본 모드는 LAN 전용이며 외부 서버로 파일을 보내지 않습니다. 인터넷 릴레이나 클라우드 기능을 추가할 경우 별도 기능으로 설계하고 명확히 알립니다.
- 수신자의 명시적 승인을 전송 전에 받습니다. 임의 파일 실행, 자동 열기, 승인 없는 저장을 하지 않습니다.
- 전송 세션마다 예측하기 어려운 인증 정보를 사용하고, 실제 기기 신원을 확인할 수 있도록 페어링 또는 세션 승인 방식을 설계합니다. LAN에 있다는 사실만으로 신뢰하지 않습니다.
- 전송 중 암호화를 사용하고, 호스트 인증 및 키 교환 방식을 프로토콜 문서에 명시합니다. 자체 암호 알고리즘을 만들지 않습니다.
- 저장 경로를 정규화해 경로 이탈, 덮어쓰기, 심볼릭 링크 악용을 방지합니다. 기존 파일과 충돌하면 사용자가 선택하도록 합니다.
- 파일명과 메타데이터를 신뢰할 수 없는 입력으로 취급합니다. 파일 크기, 파일 수, 동시 연결 수에 합리적인 제한을 두고 검사합니다.
- 로그에는 파일 내용이나 비밀 토큰을 남기지 않습니다. 진단에 필요한 정보만 최소한으로 기록합니다.

## 배포 준비

- 개발 중에도 앱의 이름, 번들 식별자, 버전 정책, 아이콘 및 권한 설명을 일관되게 관리합니다.
- 공통 아이콘 원본은 `Resources/LanShareIcon.png`와 `scripts/generate-icon.swift`에서 관리하고, macOS·iOS·Android·Windows 에셋을 같은 파일 표시와 양방향 화살표 디자인으로 유지합니다.
- macOS 배포 방식(App Store 또는 Developer ID 직접 배포)은 실제 출시 목표에 맞춰 결정합니다. 샌드박스, 서명, 공증, 자동 업데이트 필요성을 배포 방식과 함께 검토합니다.
- 로컬 네트워크 권한과 방화벽 안내, 개인정보 처리 방침, 사용 설명, 지원 연락처를 출시 전에 준비합니다.
- 서명 인증서와 배포 비밀 정보는 저장소에 커밋하지 않습니다. 릴리스 산출물의 버전과 빌드 방법을 기록합니다.
- 후속 운영체제에서는 각 스토어 정책, 권한, 서명 및 배포 절차를 별도로 검토합니다.

## Codex 작업 방식

- 먼저 저장소와 관련 지침을 확인한 뒤 현재 상태에 맞는 작은 단위로 작업합니다.
- 중요한 구조·프로토콜 결정을 문서화하고, 임시 구현을 확정된 규격처럼 취급하지 않습니다.
- 사용자가 요청하지 않은 범위 확장이나 외부 서비스 의존성을 추가하지 않습니다.
- 작업을 마치면 변경 파일, 주요 결정, 실행한 검증과 남은 제약을 요약합니다.
