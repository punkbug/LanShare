# Codex용 프로젝트 프롬프트

아래 내용을 Codex 프로젝트 지침 또는 새 작업 프롬프트로 사용하세요.

```text
이 저장소에서 LanShare라는 로컬 네트워크 파일 전송 앱을 개발한다. 제품 목표, MVP 범위, 보안 요구사항, 배포 고려사항은 먼저 README.md와 docs/PROJECT_GUIDE.md를 읽고 따른다. 저장소에 추가 지침이 있으면 함께 확인한다.

제품 목표
- 같은 Wi-Fi 또는 유선 LAN에 연결된 기기 사이에서 파일을 기기 간 직접 전송한다.
- macOS용 앱을 먼저 완성하고, 이후 iOS/iPadOS, Android, Windows 앱으로 확장한다.
- LocalSend의 로컬 직접 공유 방식과 Send Anywhere의 쉬운 연결 경험을 참고하되, 제품의 코드·브랜드·화면·프로토콜을 복제하지 않는다.
- 기본 동작에 계정, 클라우드 저장소, 외부 파일 릴레이를 요구하지 않는다.

작업 원칙
1. 구현 전에 저장소 구조, 현재 변경 사항, 관련 지침, 설치된 도구를 확인한다. 이미 있는 코드를 이유 없이 교체하지 않는다.
2. 요청된 작업에 맞춰 동작하는 가장 작은 완결 단위를 구현한다. 우선 macOS MVP를 진행하고, 다른 플랫폼을 한 번에 구현하려 하지 않는다.
3. UI, 기기 검색, 연결/전송 프로토콜, 파일 시스템 접근을 분리한다. 네트워크 프로토콜은 플랫폼 중립적인 버전 규약으로 문서화한다.
4. 네 플랫폼 앱은 4자리 코드를 mDNS/Bonjour로 광고하고, 상대 코드 입력으로 같은 LAN에서 발견된 기기를 선택한다. 앱 간 파일 데이터는 웹페이지나 외부 서버를 통과하지 않는다. 수신자는 전송 전에 파일 정보와 송신자를 확인하고 수락 또는 거절할 수 있어야 한다.
5. 큰 파일은 스트리밍하고, 진행률·속도·취소·오류를 제공한다. 전송 완료는 파일 쓰기와 검증이 끝난 뒤에만 표시한다.
6. 로컬 네트워크를 기본 신뢰 영역으로 간주하지 않는다. 세션 인증, 전송 중 암호화, 안전한 파일명/경로 처리, 충돌 확인을 설계한다. 자체 암호 방식을 만들지 않는다.
7. macOS 로컬 네트워크 권한, 방화벽 및 배포 서명/공증 준비를 고려한다. 배포 비밀 정보와 인증서는 저장소에 넣지 않는다.
8. 기술 선택이나 프로토콜 설계가 기존 문서와 달라지면 이유와 영향 범위를 문서화한다. 기능을 가장한 목업, 임시 보안 조치, 근거 없는 속도 보장을 만들지 않는다.
9. 요청된 작업의 범위와 저장소 상태에 맞는 검증을 수행하고 결과를 정확히 보고한다. 실행하지 않은 검증을 통과했다고 말하지 않는다.
10. 완료 보고에는 변경 파일, 사용자 관점의 동작 변화, 실행한 검증, 알려진 제약을 간단히 적는다.

첫 구현의 기본 방향
- 현재 저장소에 앱이 없다면 Apple 기본 기술(Swift/SwiftUI)을 우선 검토해 macOS 앱 뼈대를 만든다. 실제 환경과 도구를 확인한 뒤 선택한다.
- 첫 사용 가능한 흐름은 내 4자리 코드 표시 → 상대 코드 입력 → 파일 선택/드롭 → 수신자 승인 → LAN 직접 전송 → 진행 상태와 결과 확인이다.
- MVP에서 완성도를 유지하기 어려운 기능은 과도하게 넓히지 말고 명시적인 범위와 후속 작업으로 남긴다.
```
